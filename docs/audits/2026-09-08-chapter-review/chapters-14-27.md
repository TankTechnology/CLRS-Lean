## Highest-priority findings

### C27-A — CRITICAL: the paging algorithm type is empty on the lower-bound universe

`F/Chapter_27/Section_27_3_Online_Caching.lean:107`, `Algorithm`, requires both `step_size : ∀ C p, (step C p).card ≤ k` and `step_hit : ∀ C p, p ∈ C → step C p = C`. The former is quantified over **all** finite caches, without `C.card ≤ k`. On `Fin (k+1)`, choose `C=univ` and `p=0`; the hit law forces the oversized cache unchanged and the size law forces `k+1≤k`.

Independently checked with Lean, exit 0, in `/tmp/clrs-audit-ch27-vacuity.lean`:

```lean
example (k : Nat) (A : CLRS.OnlineCaching.Algorithm (Fin (k + 1)) k) : False := by
  have h := A.step_size Finset.univ (0 : Fin (k + 1))
  rw [A.step_hit Finset.univ (0 : Fin (k + 1)) (Finset.mem_univ _)] at h
  simp at h
```

Consequently `caching_lower_bound` (:1633) and `caching_no_c_competitive` (:1654) quantify over an impossible `A`. `lru_k_competitive` (:1092) likewise lacks a comparator instance in any ordinary page universe containing more than k pages. Pure LRU definitions and combinatorial phase lemmas remain meaningful; the advertised universal comparator/lower-bound closure does not. This is compatible with every theorem passing the axiom gate: an inconsistent *parameter structure* is a vacuity problem, not a new axiom.

**Fix:** make lawful caches a subtype, or condition size/hit preservation on `AtMost k C`; construct at least one concrete nontrivial algorithm instance on `Fin(k+1)` as an interface test; reprove the quantitative results. Also repair the model breadth: `step : Finset Page → Page → Finset Page` has no auxiliary state or time, so even after fixing admissibility it cannot represent LRU (the same resident set `{a,b}` can have opposite recency order and evict different pages on request `c`). General deterministic algorithms need a state/cache projection or history; arbitrary offline schedules need trace-level or future-aware transitions. A critical issue should be opened only after user review, not automatically.

### C14-A — MAJOR: recursive dynamic programs are advertised as tabulated polynomial-time algorithms

`L/Chapter_15/Section_15_4_Longest_Common_Subsequence.lean:295`, `lcsLength`, makes two recursive calls on a mismatch and stores no answers. Native `F/Chapter_14/Section_14_4_Longest_Common_Subsequence.lean:9` nevertheless calls this exact name “tabulated Θ(mn)”. The only cost result (:45) bounds `(m+1)(n+1)` by `4mn`; it neither counts calls nor constructs a table. On two length-n lists drawn from disjoint alphabets, both mismatch branches are evaluated repeatedly; the recursion tree grows with the central binomial coefficient, rather than quadratically. The coordinator additionally checked `/tmp/CLRSLCSAudit.lean`: an instrumented copy of the same recursion has a kernel-proved value-erasure theorem; disjoint lists of lengths 5 and 8 evaluate to 503 and 25,739 function calls, versus 36 and 81 nominal table cells. Those evaluations are concrete evidence, not a Lean asymptotic lower-bound theorem. LCS functional correctness is real (`lcsLength_upper_bound`, `lcsReconstruct_common`, `lcs_correct`) and is not challenged.

The same distinction appears in `matrixChainOpt` (`L/Chapter_15/Section_15_2_Matrix_Chain_Multiplication.lean:207`) and `bottomUpOBST` (`L/Chapter_15/Section_15_5_Optimal_Binary_Search_Trees.lean:185`): they evaluate both subintervals recursively for every split/root. The native §14.2 `matrixChainTime` (:48) is a standalone double sum; §14.5 `obstTableTime_le_cubic` (:182) merely aliases its upper bound. The advertised Θ lower directions and execution-refinement attachment are absent from these interfaces. An explicit RAM refinement is legitimately optional, but **memoized/tabulated evaluation itself is not a RAM-detail issue**.

The generic §14.3 `distinctCacheStates_le_length` (:71) proves only that a filtered finite set has cardinality at most a list length. It does not count misses, prove once-only evaluation, or bound computation by distinct states; a run recomputing one state arbitrarily often still satisfies that inequality. Repository search finds the generic cache names confined to this file, so its claim that sibling examples instantiate these interfaces is unsupported.

**Fix:** either revise the guide/CSV completion wording to “recurrence semantics, optimal reconstruction, independent table-work envelopes”, or implement finite tables with initialization, dependency order, answer refinement and an attached counter. Prove the Θ lower bounds separately. Keep already-proved optimization theorems.

### C17-A — MAJOR: equal-low distinct intervals are discarded by insertion

`L/Chapter_14/Section_14_3_Interval_Trees.lean:1722`, `intervalLt`, compares only low endpoints. `AugmentedRBTree.insertFixup` (:1037) returns the existing node if neither direction is less. Thus inserting interval `(0,10)` into the valid singleton `(0,1)` leaves the tree unchanged. Searching `(5,5)` subsequently returns `none`, although it overlaps the inserted interval. No unique-low precondition is present.

Lean-checked witness `/tmp/clrs-audit-ch17-interval.lean`, exit 0, proves the initial tree is well-augmented and satisfies the static BST predicate, `afterInsert = initial`, the failed query, and the new interval's overlap. This is about insertion membership, not an incorrect proof of static search.

The advertised `intervalSearch_after_update` (`F/Chapter_17/Section_17_3_Interval_Trees.lean:118`) proves only max-high augmentation after insertion. `IntervalTree.intervalSearch?_spec` (legacy :759) additionally requires `IsBST`; the native bridge does not prove that premise, inserted membership, or successful overlap search. The sentence “so the static search specification remains applicable” therefore omits a material premise.

**Fix:** use a total order that distinguishes intervals (or node identities/multiset insertion), or explicitly narrow the API to a unique-low map with a stated update policy. Prove insertion membership, BST ordering after erasure, and search correctness after update. Preserve the existing static theorem.

### C22-A — MAJOR: tight predecessors do not establish a shortest-path tree

`F/Chapter_22/Section_22_5_Shortest_Path_Properties.lean:271`, `predecessor`, independently chooses any minimizing incoming vertex. `predecessor_tight` (:402) proves equality of distance and predecessor distance plus edge weight. The guide (:39–40) says this makes the predecessor subgraph a shortest-paths tree rooted at the source.

That implication is false: on zero-weight edges `s→a`, `s→b`, `a→b`, `b→a`, distances are all zero, and choosing `pred(a)=b`, `pred(b)=a` satisfies every stated tightness/adjacency condition while forming a cycle disconnected from the root in the predecessor subgraph. This is a counterexample to the asserted implication/available interface, **not a claim about which witnesses Lean's opaque `Classical.choose` happens to choose**. No well-founded predecessor rank, relaxation-time provenance, or rooted-tree theorem was found; the pertinent interface test only checks the same tightness declarations.

**Fix:** thread parent pointers through strict relaxation, or choose a shortest path minimizing edge count and make predecessor depth decrease. Prove source parent absence, every reachable vertex's finite parent chain, acyclicity and path weight, and stop labeling tightness alone as Lemma/tree closure.

### C23-A — MAJOR: the diagonal test's two “directions” are one logical direction

`F/Chapter_23/Section_23_2_Floyd_Warshall.lean:537` says “We prove both directions”. `floydWarshall_nonneg_diag` (:543) is `NoNegCycle → diagonal≥0`; `negative_diagonal_implies_negative_cycle` (:555) is `diagonal<0 → negative cycle`, the contrapositive direction of the first, not `negative cycle → some negative diagonal`. The latter is labeled “Completeness”.

Moreover `weightMatrix` (`F/Chapter_23/Section_23_1_All_Pairs_Model.lean:34`) overwrites every diagonal with zero while `WeightedGraph` permits self-edges. A one-vertex graph with a negative self-loop consequently has zero Floyd–Warshall diagonal, so unrestricted completeness would actually be false for this representation. Correctness under `NoNegCycle` is unaffected.

**Fix:** retain `min 0 w(i,i)` for diagonal self-edges, or explicitly rule them out in the detector domain; then prove `¬NoNegCycle → ∃i, diagonal i<0`. Reclassify the existing implication as soundness. Johnson's section prose (:15) also promises BF detects/aborts on negative cycles, while `johnsonAllPairsDist` (:855) requires a `NoNegCycle` proof and has no failure result; describe this as the valid-input construction until a detector wrapper exists.

### C23-B — MAJOR: advertised execution attachment exceeds the cost definitions

The Chapter 23 guide's coverage boundary promises cost bounds “bound to the real executable constructions”. `johnsonCost` (`F/Chapter_23/Section_23_3_Johnsons_Algorithm.lean:942`) is augmented-graph `bellmanFordWork` plus `|V|*dijkstraWork`. `dijkstraWork` (`F/Chapter_22/Section_22_3_Dijkstra.lean:168`) is simply `(V+E)(log₂V+1)`. The actual `dijkstraStep` (:207) uses an existential minimum and `Classical.choose`; it has neither a heap nor an attached operation counter. Thus `johnsonCost_eq` is correct algebra for an abstract binary-heap budget, not a refinement theorem for the actual loop.

Likewise `D` in Floyd–Warshall (:51) is a function-valued recurrence with repeated evaluations; `floydWarshallCost` (:898) sums an independent `V²` budget per pivot. Repeated squaring's cost similarly assumes constant-time matrix cell access. These are useful algorithmic envelopes but lack table materialization/execution equivalence.

**Fix:** accurately label abstract budgets, or produce costed table/queue algorithms refining these distance functions and prove equalities from their counters. Do not report the absence of a *RAM* model as this finding; the missing link is between existing value computation and charged work.

### C24-A — MAJOR: V³ augmentation bound is advertised as sparse O(VE) / O(VE²)

`F/Chapter_24/Section_24_2_Edmonds_Karp/S3_WorkAnalysis.lean:542`, `augmentation_count_bound`, proves at most `Fintype.card (V×V)*Fintype.card V = V³` augmentations by injecting into all ordered vertex pairs and distances. The guide (:53–56) says this gives O(VE²) after charging O(E) for BFS. For sparse E=Θ(V), the displayed bound gives O(V⁴), while VE²=Θ(V³). A subset-of-support argument replacing V² by O(E) is required; no such end-to-end EK theorem was found. The new support-indexed BFS is real, and Chapter 25's matching-specific attached cost is real, but neither silently sharpens this EK count.

**Fix:** prove every critical pair lies in the forward/reverse positive-capacity support, inject into that support times distance, and attach the costed support BFS and augmentation counter to one EK run. Until then advertise the actual V³ count and separate BFS theorem.

### C21-A / C24-B — MAJOR completion boundaries: conditional execution traces are not constructed to completion

For Prim, `frontierRun_refines_PrimTrace` (`F/Chapter_21/Section_21_2_Kruskal_And_Prim/S3_ExecutablePrim.lean:477`) proves each returned edge is a valid light frontier choice, for *arbitrary fuel*. `prim_minimum_spanning_tree` (main section :1917) additionally requires a `PrimCertificate`, whose fields include final spanning coverage (:1822). Repository-wide callers do not construct that certificate from `frontierRun`. On a connected graph with an edge, fuel zero yields a valid empty `PrimTrace` but not a spanning tree. The trace theorem is correct; the advertised executable MST correctness chain still lacks a progress/coverage bridge. Its binary heap cost bounds (:511 onward) quantify over independently supplied `HeapRound` traces and assumed decrease/extraction counts; they are not attached to `frontierRun`, which rebuilds the frontier queue from all graph edges.

For relabel-to-front, `RelabelToFrontRun` (`F/Chapter_24/Section_24_5_Relabel_To_Front.lean:1295`) bundles a `Run` plus an assumed discharge discipline: no vertex makes two nonsaturating pushes without an intervening relabel. `step_count_bound_V3` (:1439) proves a genuine bound for that class. No implementation of current-neighbor pointers/list movement, generator of such a run, initial-preflow construction, or completion-to-no-overflow theorem was found. Raw legal-operation traces and mathematical conditional theorems are valid; the actual scheduling obligation is assumed.

**Fix:** Prim: prove enough fuel makes the root component span every connected input, then construct `PrimCertificate` and combine with existing MST theorem. RTF: define initialized discharge and list loop, prove its discipline and termination, then apply `maximal_of_no_overflow`. Otherwise change completion claims to conditional trace analysis. Disconnected graphs are explicitly excluded by MST/spanning premises; do not call that a false theorem, but do not advertise a minimum spanning forest endpoint without proving one.

### C27-B — MAJOR lower-bound interface weakness beyond paging vacuity

`rentThenBuy_lower_bound` (:181) and `skiRental_lower_bound` (:222) in `F/Chapter_27/Section_27_1_Waiting_For_Elevator.lean` conclude `∃ T, c*optCost T ≤ onlineCost T` without requiring positive T or positive offline cost. T=0 makes both costs zero, so the *statement* would hold for any c. The bodies construct positive witnesses, but the exported theorem discards the condition needed to infer that a smaller ratio is impossible. Add `0<T` or `0<optCost T` to the existential and a direct competitive-ratio exclusion corollary.

After repairing C27-A, `caching_no_c_competitive` (:1654) still ranges only over `c : Nat` and uses one fixed request length `k³`, with no additive constant. This does not state the advertised exclusion of every real c<k under the additive-constant notion used by `lru_k_competitive` (which allows +k). The stronger arbitrary-N theorem can support the missing argument once the algorithm domain is inhabited. Add `∀c:ℝ, c<k → ∀b, ∃σ, costA σ > c*costOffline σ+b` with the appropriate nonnegative conventions.
