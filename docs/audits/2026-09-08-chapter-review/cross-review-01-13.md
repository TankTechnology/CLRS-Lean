## Strong findings challenged

### Chapter 8: accepted, with abstract/executable distinction

Counting-sort counterexample is source-derived, independent of machine overhead. `scatter` iterates all `maxKey+1` keys and invokes `reverseBucket`, whose fold evaluates the key test once for every input. For n=maxKey=10, there are 110 tests versus assigned 42; for maxKey=n, tests are n(n+1), contradicting any proposed O(n+maxKey) bound for these key tests. Source cost243 describes initialization/count/prefix/scatter passes that are not called by113. Radix715 uses the functional filter sorter, so importing array correctness elsewhere does not repair its count.

Bucket-sort contains a genuine **disclosed abstract** model at537–547 expressly saying it does not instrument the repeated-filter program. That old abstraction alone is not a finding. The later “Costed executable bucket sort” at652–667 says its n term counts `distributeBuckets` but pairs the old sorter with the formula; repository references show distributor only in its own size proof/interface checks, not the sorter. Thus late completion prose58 and655 is wrong. Under every n-bucket assignment, full-input filtering makes n² key tests; averaging cannot remove them. Preserve valid occupancy moments and deterministic sorting. Fix call graph plus a distribution-content refinement, or withdraw executable-cost labels. A formula pairing and rfl erasure alone do not constitute runtime instrumentation.

The decision-tree issue is narrower. An extra self-comparison always branches left; arbitrary right subtree raises structural height without raising reachable run cost. This refutes the height comment's equality interpretation, not the structural lower-bound theorem or the true mathematical lower bound. An additional reachable-run/prefix-code argument is needed. Keep it below the confirmed executable-cost defects.

### Chapter 11: invariant defect accepted; construction remains a qualified gap

`sec_inj` universally quantifies x,y in K and only asks same primary/secondary coordinates. Its own comment requires x,y∈keys. With keys={a}, one bucket, constant secondary hash, and only slot0 storing a, search correctly rejects b≠a after comparing the stored value, but the structure excludes this table by forcing a=b. This proves overrestriction, not logical inconsistency of every table: the current unbounded Nat slot codomain permits globally injective hashes on many universes. Do not claim PerfectHashTable universally uninhabited. Add the two stored-key premises; separately link finite allocated slot bounds if claiming the FKS space implementation.

`perfectSearch_iff_mem` only uses table_stores_keys/table_only_keys. Weakening sec_inj therefore preserves this proof. The theorem is a membership equivalence under abstract function lookup, not itself a measured runtime theorem; O(1) additionally treats hash/lookup primitives as constant-cost.

The trials probability is on all finite function assignments, not an arbitrary universal family; retain that finite model. `failedTrials+1` after t failed trials is t+1, while a continuation can need t+2 or more, hence a lower truncation. Uniform expectation bounds can support an eventual waiting-time theorem, but require a limit/termination argument. `constructionCost = n+2*space` is a sound analytic upper-budget expression whose final theorem simply averages it. Recommend MINOR/UNCERTAIN for builder completion, rather than treating the formula's true bound as mathematically false. Section primary MAJOR is driven by the concrete quantifier mismatch.

### Chapter 13: accepted without expanding into a new proof audit

The two primitives only write the pivot pair and detached child's parent. Root and former parent's child field are never modified. Validating root update is therefore a semantic necessity, not a representation preference. StoreRepr's sentinel constructor is unconditionally available while node constructor permits the sentinel address, so a cyclic sentinel cell admits empty and singleton interpretations. Strengthen sentinel/footprint/parent invariants and prove primitive refinement.

Insert/delete counters are separate RBTree→Nat formulas; their proofs use height inequalities. InsertCost does not visit rebalance cases, deleteCost assumes a height join budget without proving a costed join bound. Asymptotic O(height) for suitable real algorithms may be true, but precise claimed pointer costs are unsupported. Preserve the functional WellFormed correctness claims and distinguish them from pointer implementation.
