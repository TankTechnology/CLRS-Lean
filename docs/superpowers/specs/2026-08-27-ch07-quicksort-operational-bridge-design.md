# Chapter 7 quicksort operational comparison bridge

## Goal

Close GitHub issue #330 by proving, for every finite priority permutation, that
the existing CLRS rank-pair trace counter is pointwise equal to the recursive
comparison counter of the executable first-pivot quicksort:

```lean
theorem randomizedQuicksortComparisonCount_eq_quickSortComparisons
    {n : Nat} (priority : Equiv.Perm (Fin n)) :
    randomizedQuicksortComparisonCount priority =
      quickSortComparisons (randomizedQuicksortInput priority)
```

The theorem must then transport the existing exact expectation formula and
`Theta(n log n)` result to a random variable defined directly from
`quickSortComparisons`.

## Chosen architecture

Use the classical quicksort--binary-search-tree correspondence and reuse the
mature Chapter 12 theorem family for randomly built BSTs.  Both existing
abstraction layers remain unchanged:

1. Chapter 7 supplies the executable first-pivot quicksort, its recursive
   comparison counter, the explicit permutation sample, and the CLRS pair
   predicate.
2. Chapter 12 supplies `buildFromList`, `buildFromPerm`, `depth`,
   `isAncestorOf`, and the proved equivalence between ancestry and being first
   in a closed key interval.
3. New focused bridge modules prove that both Chapter 7 counters equal the sum
   of BST depths for the tree generated by the same permutation.

Only the new operational bridge imports Chapter 12.  Existing Chapter 7 core,
probability, execution, and expectation modules keep their present dependency
surface and public declarations.

## Rejected alternatives

### Independent recursive comparison trace

Define a new list or finite-set trace by following quicksort recursion and
prove its membership is the endpoint-first interval predicate.  This avoids a
cross-chapter import, but duplicates the hard interval/filter induction already
proved in Chapter 12 and creates another public trace representation.

### Redefine the current pair counter as `quickSortComparisons`

Changing `randomizedQuicksortComparisonCount` would make the desired equality
definitional, but would invalidate its current indicator decomposition and
turn the expectation proof into the same missing theorem under another name.
It also needlessly changes an accepted public interface.

## Module boundaries

### `OperationalBridge/UnorderedPairs.lean`

Provide the finite triangular-sum identity that rewrites all strict ordered
pairs as one `i < j` entry containing both orientations.  This file depends
only on Mathlib and keeps reindexing details out of the semantic proofs.

### `OperationalBridge/ExecutionToBST.lean`

Relate the recursive cost model to the BST built from the same distinct input.
The central proof is by fuel induction with a `List.Nodup` invariant:

- the left quicksort partition (`x <= pivot`) equals the strict BST partition
  (`x < pivot`) because the tail does not contain the pivot;
- the two filtered lists remain duplicate-free and have enough remaining
  fuel;
- the root contributes exactly the number of tail elements;
- every subtree key gains one unit of depth at the new root.

The specialized result states that
`quickSortComparisons (randomizedQuicksortInput priority)` equals the sum of
the depths of all keys in `Chapter12.buildFromPerm priority`.

### `OperationalBridge/PairTraceToBST.lean`

Relate the CLRS pair predicate to the same BST:

- identify Chapter 7's `rangeFin` with the closed `Finset.Icc` interval;
- identify Chapter 7's `IsFirstIn` with Chapter 12's `isFirstOf`;
- use `isAncestorOf_buildFromPerm_iff_firstInInterval` to prove that ranks
  `i < j` are compared exactly when `i` is an ancestor of `j` or `j` is an
  ancestor of `i`;
- use Chapter 12's exact ancestor-count/depth theorems plus the triangular-sum
  identity to show the pair counter equals the total BST depth.

No probabilistic independence premise is introduced; this layer is pointwise
in a single permutation.

### `OperationalBridge.lean`

Combine the two equalities through the common total-depth normal form.  Expose:

- the pointwise counter equality;
- `operationalRandomizedQuicksortExpectedComparisons`, defined by averaging
  the actual recursive counter;
- equality with `explicitRandomizedQuicksortExpectedComparisons`;
- the exact closed form and inherited `Theta(n log n)` theorem.

## Edge cases and proof obligations

- `n = 0` and `n = 1` must reduce to zero comparisons and zero total depth.
- Duplicate inputs are not claimed by the BST bridge; the general execution
  theorem explicitly requires `List.Nodup`.  The sampled permutation input
  discharges this condition.
- The quicksort left partition uses `<=` while BST insertion uses `<`; the
  no-pivot-in-tail lemma is an explicit audited bridge, not a simplifier
  accident.
- Natural-number subtraction is avoided in the central equality.  Counts are
  expressed as strict-ancestor indicators, with the self-ancestor term split
  explicitly before applying the triangular-sum lemma.
- Chapter 12 remains unchanged unless a genuinely missing reusable lemma is
  found.  Any such addition must be a direct theorem wrapper rather than a
  rewrite of its existing development.

## Verification strategy

Development uses a red-green interface loop.  The desired public theorem names
are added to `Tests/FourthEdition_Chapter_07_Interface.lean` first and must fail
as unknown identifiers before implementation.

Focused verification:

```text
lake env lean <each new bridge module>
lake build CLRSLean.FourthEdition.Chapter_07
lake env lean Tests/FourthEdition_Chapter_07_Interface.lean
lake env lean Tests/Trust/Chapter_07.lean
```

Final verification:

```text
rg -n '\b(sorry|admit|axiom)\b' <new modules and tests>
git diff --check
python3 scripts/check_repository.py
lake build CLRSLean
```

Website generation and deployment are outside this proof task.
