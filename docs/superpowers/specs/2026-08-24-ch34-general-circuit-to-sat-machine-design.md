# Chapter 34 GeneralCircuitSAT-to-SAT Machine Design

## Goal

Close the last concrete reduction gap in the Chapter 34 Section 34.4 chain by
proving that the already-defined total map

```lean
generalCircuitToSATMap : List CircuitSym → List FormulaSym
```

is computed by one fixed polynomial-time TM2.  Combine that result with the
existing semantic theorem and the existing SAT-to-3-CNF-to-CLIQUE reductions to
publish:

```lean
generalCircuitSAT_reducible_to_SAT :
  PolyTimeReducible GeneralCircuitSAT SAT

clique_npHard : NPHard CLIQUE
clique_npComplete : NPComplete CLIQUE
```

This is a proof subproject, not a general-purpose compiler project.  The
machine exists only to discharge the executable polynomial-time obligation in
the textbook reduction.

## Existing verified boundary

The mathematical and representation-level parts are already proved:

- `generalCircuitToFormula` asserts the designated output and one consistency
  equation for every gate;
- `generalCircuitSatisfiable_iff_satisfiable_generalCircuitToFormula` proves
  the typed semantic equivalence for well-formed circuits;
- `generalCircuitToSATMap` is total on raw strings and maps malformed or
  decoded-but-ill-formed strings to `enc (.const false)`;
- `generalCircuitToSATMap_mem_SAT_iff` proves exact raw-language preservation;
- `generalCircuitToSATMap_length_le` bounds output length by
  `32 * (input.length + 1) ^ 3`;
- `generalCircuitSAT_npComplete` proves the source is NP-complete;
- the concrete reductions `SAT ≤p ThreeCNFSat` and
  `ThreeCNFSat ≤p CLIQUE` already exist;
- `generalCLIQUE_mem_ClassNP` supplies the target membership side.

An output-length theorem is not a polynomial-time computability theorem.  The
missing obligation is an actual fixed TM2 together with exact output semantics
and a uniform input-length polynomial runtime bound.

## Chosen architecture

The reduction is implemented as the composition of two fixed machines over a
small internal finite alphabet.

### 1. Guarded circuit normalizer

The first machine reads the raw `CircuitSym` input and produces one of two
canonical internal records:

```text
invalid

valid
  inputCount
  outputIndex
  gateCount
  gate rows annotated by their chronological gate index
```

All natural numbers remain unary.  A gate row records its finite gate tag and
its zero, one, or two unary operands.  The normalizer accepts exactly the raw
strings for which `decodeCircuit input = some c` and `c.WellFormed`.  It checks:

- the input-count header and complete input consumption;
- the exact arity and delimiters of every gate encoding;
- input-gate operands below `inputCount`;
- dependency operands below the current gate index;
- a single trailing output record;
- the output index below the final gate count.

The normalizer stages rows on work stacks.  It emits the `valid` record only
after every check succeeds.  Any failure clears staged work and emits exactly
`invalid`.  This ensures that no malformed prefix can leak a partial SAT
formula.

The semantic theorem is stated on every raw input:

```lean
normalizeGeneralCircuit input =
  match decodeCircuit input with
  | some c => if c.WellFormed then encodeNormalizedCircuit c else [invalid]
  | none => [invalid]
```

The existing general-circuit verifier is not composed as a black box because
it consumes a paired certificate/input stream and computes gate values.  The
new normalizer instead reuses its proven design patterns and local lemmas for
complete parsing, unary counters, stack restoration, canonical rejection, and
input-length bounds.

### 2. Formula emitter

The second machine consumes only canonical normalizer output.

- On `[invalid]`, it emits `enc (.const false)`.
- On `encodeNormalizedCircuit c`, it emits exactly
  `enc (generalCircuitToFormula c)`.

For a valid record it emits the prefix-polish stream

```text
andMark
varEnc (inputCount + outputIndex)
for every gate i in chronological order:
  andMark
  iffMark
  varEnc (inputCount + i)
  encoded expression of gate i
lit true
```

The annotated gate index removes the need to reconstruct an unbounded index in
finite control.  Unary variable indices are generated by copying the stored
`inputCount` prefix and appending either the annotated gate index or a source
operand.  Gate tags determine only a finite output template.  Formula chunks
are staged or emitted in reverse and then passed through the existing verified
reversal machine, so their final order agrees with `enc` definitionally rather
than through a global permutation argument.

The emitter's principal theorem is:

```lean
emitGeneralCircuitFormula (normalizeGeneralCircuit input) =
  generalCircuitToSATMap input
```

## Machine composition and runtime

Each stage publishes a `PolyTimeComputable` theorem with a named explicit
`Polynomial Nat` bound.  The proof uses the repository's concrete TM2
composition theorem; it does not appeal to a non-executable computability
axiom or to output size alone.

The normalizer makes a bounded number of restoring scans for each unary field
and gate row.  The emitter copies at most input-length-sized unary counters for
at most input-length-many rows.  Coarse bounds are acceptable: the public
runtime polynomial need not match the existing cubic output-size bound, but it
must depend only on the original raw input length and must cover malformed
inputs as well as successful inputs.

The public machine theorem is:

```lean
generalCircuitToSATMap_polyTimeComputable :
  PolyTimeComputable generalCircuitToSATMap
```

The reduction is then assembled without redefining the map:

```lean
generalCircuitSAT_reducible_to_SAT :
  PolyTimeReducible GeneralCircuitSAT SAT :=
⟨generalCircuitToSATMap,
  generalCircuitToSATMap_polyTimeComputable,
  generalCircuitToSATMap_mem_SAT_iff⟩
```

Finally, reduction transitivity yields

```text
GeneralCircuitSAT ≤p SAT ≤p ThreeCNFSat ≤p CLIQUE,
```

after which `NPHard.of_reducible` and the existing CLIQUE NP verifier yield
`clique_npHard` and `clique_npComplete`.

## Focused module boundaries

All new proof files remain small and live under
`GeneralCircuit/ToSAT/Machine/`.  Facade files contain imports only.

- `InternalEncoding/Basic.lean`: finite work alphabet and normalized record
  grammar;
- `InternalEncoding/RoundTrip.lean`: encoder/decoder and canonical structure
  lemmas;
- `Normalizer/Basic.lean`: machine stacks, labels, state, and program;
- `Normalizer/UnaryField.lean`: exact unary parse/copy phases;
- `Normalizer/GateRow.lean`: gate arity and operand-bound phases;
- `Normalizer/Run.lean`: valid and invalid whole-input behavior;
- `Normalizer/Runtime.lean`: exact/coarse step accounting;
- `Normalizer/PolynomialRuntime.lean`: uniform polynomial-time theorem;
- `Emitter/Basic.lean`: emitter stacks, labels, state, and program;
- `Emitter/Variable.lean`: unary `varEnc` emission;
- `Emitter/Gate.lean`: per-gate expression and consistency chunks;
- `Emitter/Family.lean`: chronological gate-family emission;
- `Emitter/Run.lean`: invalid and valid whole-record semantics;
- `Emitter/Runtime.lean`: step accounting;
- `Emitter/PolynomialRuntime.lean`: uniform polynomial-time theorem;
- `Composition.lean`: equality with `generalCircuitToSATMap` and the composed
  `PolyTimeComputable` result;
- `Reduction.lean`: language reduction and `CLIQUE` hardness/completeness;
- `Machine.lean`: public import facade.

If one phase becomes large, its exact-step theorem and its polynomial bound are
split rather than extending the same file.  Existing large files such as
`CircuitSAT.lean` and `GeneralCircuit/Encoding.lean` are consumed through their
public interfaces and are not enlarged.

## Error semantics

The behavior on bad inputs is part of the theorem, not an implementation
convenience:

- malformed circuit encoding → `enc (.const false)`;
- canonical but ill-formed circuit → `enc (.const false)`;
- empty input or trailing garbage → `enc (.const false)`;
- well-formed circuit, whether satisfiable or not → the exact consistency
  formula encoding.

The machine must halt within the same public polynomial budget in all four
cases.  Reject cleanup lemmas therefore precede the successful whole-run
theorem instead of being left until runtime assembly.

## Verification strategy

Public theorem names are introduced first in focused interface tests so that a
missing implementation fails for the expected identifier.

Required focused tests cover:

- internal encoding round trips;
- malformed, truncated, and trailing-garbage normalization;
- every gate constructor and its operand-bound rejection cases;
- exact formula output for constant, input, unary, and binary gates;
- equality with `generalCircuitToSATMap` on arbitrary raw input;
- the reduction theorem and final `NPComplete CLIQUE` interface.

Each coherent stage is committed only after its narrow Lean tests pass.  The
final checkpoint additionally requires:

```text
lake env lean Tests/Chapter_34_GeneralCircuit_ToSAT_Machine.lean
lake env lean Tests/Chapter_34_GeneralClique_Interface.lean
lake env lean Tests/Chapter_34_Interface.lean
lake build CLRSLean.Chapter_34
python3 scripts/check_literate_config.py
python3 scripts/check_site_consistency.py
python3 scripts/check_repository.py
git diff --check
```

An axiom audit is run over all new machine files and the published reduction
theorems.  `sorry`, `admit`, and new project axioms are not permitted.

## Staged acceptance checkpoints

1. The internal normalized record has proved round trips and size bounds.
2. The normalizer computes the exact guarded semantic map on every raw input.
3. The normalizer has a uniform polynomial runtime theorem.
4. The emitter computes the exact formula encoding on invalid and valid
   normalized records.
5. The emitter has a uniform polynomial runtime theorem.
6. The composed machine computes `generalCircuitToSATMap` in polynomial time.
7. `GeneralCircuitSAT ≤p SAT` compiles through the public interface.
8. The existing reduction chain publishes `clique_npHard` and
   `clique_npComplete` without weakening the definition of `CLIQUE`.
9. Chapter documentation and navigation record the closed Section 34.4 chain.

## Non-goals

- No separate polynomial-time SAT verifier is required for this reduction.
- No replacement of the existing formula or circuit encodings is allowed.
- No direct general-circuit-to-CLIQUE gadget construction is added.
- No work on VERTEX-COVER, HAM-CYCLE, TSP, or SUBSET-SUM is mixed into this
  proof block.
- No claim that all of Chapter 34 is complete follows from closing Section
  34.4; Section 34.5 remains a separate documented subproject.
