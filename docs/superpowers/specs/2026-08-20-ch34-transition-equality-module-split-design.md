# Chapter 34 Transition Equality Module Split

## Goal

Close the remaining equality-alignment boundary of the concrete Cook--Levin
transition source without growing another monolithic Lean file.  The final
public theorem must identify the delimiter-exact frames generated by the fixed
polynomial-time TM2 with the canonical
`transitionScriptFromSeed ... .eqFrames` list.

## Accepted Structure

The unfinished equality alignment is divided by stable theorem interface:

1. `GeneratorTransitionEqSlotIntervals.lean`
   owns only natural interval concatenation, fixed-stack prefix sums, and
   stack-offset arithmetic.
2. `GeneratorTransitionEqSlotEnumeration.lean`
   owns the explicit prefix/height/cell slot lists and proves their length and
   canonical `cfgSlotEquivFin` order.
3. `GeneratorTransitionEqSegmentAlignment.lean`
   relates the runtime segment progressions to the explicit public/workspace
   slot enumeration, including every generated `(previous, left, right)` row.
4. `GeneratorTransitionEqCanonicalAlignment.lean`
   proves generated frames equal the existing seed-derived transition script
   frames and lifts the result to the verifier transition family.
5. `GeneratorTransitionEqAlignment.lean`
   is a lightweight facade importing the completed alignment chain.

`GeneratorTransitionInputCompiler.lean` imports only the facade.  Lower layers
must not import higher layers, so focused builds never create an import cycle.

## Size and Interface Rules

- Target roughly 100--250 lines per new theorem-bearing file.
- Each file has one semantic obligation and a small public theorem block.
- Generic interval lemmas stay independent of TM2 execution proofs.
- The canonical-alignment file does not unfold the progression controller.
- Existing pushed `GeneratorTransitionEqSource.lean` and
  `GeneratorTransitionEqFrames.lean` remain stable unless profiling shows that
  their own direct compilation is a bottleneck.
- No theorem is weakened during the split; the byte-exact and polynomial-time
  TM2 interfaces already pushed remain unchanged.

## Verification and Checkpoints

For each layer:

1. expose its intended public theorem in the focused transition-input test;
2. build only that module while developing;
3. run the focused test, `git diff --check`, unfinished-proof scan, and axiom
   audit before committing;
4. commit and push the layer independently;
5. run the Chapter 34 root check when the facade or a reader-facing theorem is
   changed.

The first implementation checkpoint is the interval/slot-enumeration layer.
The next is segment-to-slot alignment.  The final checkpoint is canonical
frame equality and its raw-verifier family corollary.

## Non-Goals

- No redesign of the already verified progression or delimiter controllers.
- No broad renaming or unrelated Chapter 34 cleanup.
- No move to native evaluation or runtime data in finite control.
- No claim that Cook--Levin is complete until the continuous transition-family
  source and complete verifier-circuit generator are closed.
