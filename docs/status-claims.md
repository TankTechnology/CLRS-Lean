# Chapter-status claims and their single update path

CLRS-Lean records chapter and section completion in two machine-readable
ledgers, and a number of documents restate that status in prose.  This page
defines which claims are *generated* from the ledgers, which are *hand-written*
and must be kept in step, and the one update path to follow when a theorem is
proved or a gap is closed.

## Source of truth

Two files own completion status; everything else is derived or advisory.

- [`docs/clrs-proof-progress.csv`](clrs-proof-progress.csv) — per-chapter
  `repo_status`, `tracked_key_theorems`, `proved_tracked_theorems`,
  `edition_gap_units`, and the reader-facing completion summary.
- [`docs/clrs-fourth-edition-map.csv`](clrs-fourth-edition-map.csv) —
  per-section `migration_state` (`native`, `facade`, `partial`,
  `not-started`, `online-material`) and the section coverage boundary.

When these two disagree, the map is authoritative for *section* state and the
progress CSV is authoritative for *chapter* status and theorem counts.  The
repository checks reject any disagreement between them.

## Generated views

These files are produced mechanically from the ledgers and must never be edited
by hand:

| File | Generated by |
| --- | --- |
| `CLRSLean/Progress.lean` | `python3 scripts/check_progress_csv.py --write-dashboard` |
| `README.md` (progress table) | `python3 scripts/gen_readme_table.py` |

`check_repository.py` verifies they are up to date (`--check-dashboard` and
`--check` respectively), so a ledger edit that skips regeneration fails CI.

## Hand-written views and their update obligations

These documents restate status for readers.  They are **not** generated because
each carries structure that the ledgers do not (proof narratives, migration
history, deferred-scope notes).  When a claim here drifts from the ledgers, the
status-claim check fails.

| Document | Obligation |
| --- | --- |
| `docs/migrations/clrs4.md` | The chapter-mapping table's `none` / source column must match the edition map's started sections. |
| `docs/proof-status-board.md` | Frozen totals ("all 35 chapters represented", "the only `partial` row") must match the progress CSV. |
| `docs/status/blocked-and-deferred.md` | Every `Status:` label must be one of the fixed vocabulary below; referenced sections must exist. |
| `docs/proof-map.md` | Per-section `Status:`/proved-theorem lists track the same chapters the map marks started. |
| Chapter guides and section `/-!` blocks | A section may describe gaps only when the map/CSV actually leave that boundary open. |

Blocked-and-deferred status vocabulary:

- `deferred-implementation`
- `deferred-low-level-implementation`
- `proved-abstract`
- `future-work`
- `partial-proof`
- `proved`

## The one update path for a proved theorem or closed gap

1. Edit `docs/clrs-fourth-edition-map.csv` (section `migration_state` /
   `source_modules` / `coverage_note`) and `docs/clrs-proof-progress.csv`
   (chapter `repo_status`, counts, `edition_gap_units`, summaries) in the same
   commit as the proof work.
2. Regenerate the derived views:
   ```bash
   python3 scripts/check_progress_csv.py --write-dashboard
   python3 scripts/gen_readme_table.py
   ```
3. Update the hand-written views that named the old boundary —
   `docs/proof-map.md`, `docs/migrations/clrs4.md`,
   `docs/proof-status-board.md`, `docs/status/blocked-and-deferred.md`, and any
   chapter-guide or `/-!` "current gaps" prose.
4. Run `python3 scripts/check_repository.py`.  It runs
   `scripts/check_status_claims.py`, which fails if any secondary view still
   reports the old status.

Editing only `README.md` or `CLRSLean/Progress.lean` is not a supported update:
both are generated, and doing so leaves the ledgers and prose stale.  A change
that only bumps a proof count to 100% without clearing the corresponding
edition-map gap is likewise rejected: the gap count and the map state must move
together.

## CI

`check_repository.py` runs `check_status_claims.py` and its unit tests
(`scripts/test_check_status_claims.py`) on every check; the GitHub workflows
invoke `check_repository.py`.
